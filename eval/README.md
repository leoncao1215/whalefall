# 评测

没有评测的记忆系统 = 没有记忆。

## 文件

| 文件 | 作用 |
| --- | --- |
| `corpus.jsonl` | 30 条合成历史（2026-10-14 → 11-01），人物：小鲸鱼、阿哲、妈妈 |
| `questions.jsonl` | 15 条**关键词题**：题目自带查询计划（关键词/时间窗/实体） |
| `questions-hard.jsonl` | 5 条**换句话问题**：不含原文关键词，考语义 |
| `report.md` | 跑完生成 |

跑法：

```bash
npm run eval          # 生成 eval/report.md
node src/cli.mjs eval # 只看终端输出
```

## 当前基线（2026-11-01）

| 集合 | recall@5 | MRR | p95 |
| --- | --- | --- | --- |
| 关键词题 | **100%** (15/15) | 0.967 | 0.4ms |
| 换句话问 | **0%** (0/5) | 0.000 | 0.1ms |

这个对比是**结论，不是失败**：

- 检索层是纯词法的，只要问题里出现原文关键词，召回和排序都没问题；
- 一旦换成"土特产""小动物""别喝冰的"这种说法，词法检索直接归零。

也就是说，**现在的瓶颈不在检索算法，而在"把问题翻译成查询"**（query planning）。
下一步优先级因此很清楚：先让模型产出查询计划（关键词扩展 + 时间/实体过滤），
而不是急着上向量库——向量库解决的是另一类问题（近义），而这里的缺口是"不知道去哪找"。

## 指标

- **recall@5**：正确答案是否出现在前 5 条。
- **MRR**：第一个正确结果的排名倒数均值。
- **p95 耗时**：检索层本身的延迟（不含模型）。

## 原则

1. 题目用**真实口吻**写，允许"那个东西""上次"这种指代。
2. 每题都要能人工判断对错，不写"总结我的人生"。
3. 改检索/摘要前先跑基线；掉了就是退步。
4. 合成语料只用来回归**机制**；真实效果要用真实历史重跑。
