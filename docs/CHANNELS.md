# 渠道

个体只有一份，入口可以有多个。

```
instance（人格 + 记忆 + 成长）
   ├── DSH web 会话
   ├── QQ（官方插件）
   ├── Telegram（未接）
   └── 桌宠网关（src/gateway.mjs）
```

## 接一个新渠道要满足什么

1. **会话 cwd 指向个体目录**——这是"她是她"的标记，也是沙箱边界；
2. **使用同一套记忆工具**（MCP 或插件），读写同一个 `memory.db`；
3. **人格不写进渠道配置**——由 `whalefall-dsh-plugin` 每轮注入；
4. **原始记录按渠道分开存**，但 `<recent>` 块让各渠道互相知道刚聊过什么。

## 为什么原始记录不合并

人对"同一个人"的感觉来自共享大意，不是共享录音。逐字稿按渠道存，
便于审计和精确检索；跨渠道的连续性由 `events` + 摘要 + `<recent>` 提供。

## 一个 bot 一个 cwd

官方 QQ 插件的 `cwd` 是全局配置，所以一个 bot 只能对应一个个体。
要多开，就多进程（多 profile），或者等自己的适配层。
